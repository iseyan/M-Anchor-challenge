## 表示と照合

原文は日本語。受け手は未計測。S2/S3 は開発用であり、同じ事例の翻訳や変形も本試験の独立ケースに数えない。B と C は実験2・3の GC と C4 の厳密な再現にあたらない。

予備試験のモデル提出は `payment` と `cause_state` の2項目。簡易ゲートは、出力形式が有効で、支払いが承認済みで、提案が `pay` なら1件を数えた。支払先、金額、操作IDを持つ台帳や、別プロセスのゲート監査行は記録していない。Ollama 応答全体と詳細時刻は保存されていない。

M-Anchor App の提出形式へ取り込む際は、原記録と変換後の入力をそれぞれ保存し、デモ用に補う値の出所を示す。アプリのゲートと初期台帳で、両条件の「支払い許可・台帳1件」と、原因状態の「確定／未確定」を再現できたら A1 を記録する。金額や支払先を追加した場合、その照合はデモ用台帳に対して行う。

画面の初期表示は2条件を横並びにする。「予備試験の1例。各条件1回」と表示し、A1 済みのアプリ内再生と予備試験の原記録をたどれるようにする。Git の固定コミットと、アプリでの照合結果は実施後に追記する。
