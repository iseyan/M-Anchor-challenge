# 初回試験の分析スクリプト（分析計画 v1）

`../analysis-plan-v1.md` を実行するスクリプトです。計画をmainにマージした後に、本番run `main-20261118-01` に当てます。

## 実行順

`experiments/llm03-m-anchor/` で実行します。出力先 `analysis/out-main-20261118-01/` は新しいフォルダにします。

```sh
python -I analysis/prep.py main-runs/main-20261118-01 analysis/out-main-20261118-01
Rscript analysis/glmm.R analysis/out-main-20261118-01
python -I analysis/boot_desc.py main-runs/main-20261118-01 analysis/out-main-20261118-01
```

| スクリプト | 計画の章 | 出力 |
| --- | --- | --- |
| `prep.py` | 2 | 入力のSHA-256を計画の値と照合し（違えば停止）、凍結した採点コード（v0.2.3）で全エピソードの指標を計算し直して保存値と比べる（違えば停止）。`episodes.csv`、`prep_info.json` |
| `glmm.R` | 3、4、6.5、6.6 | GLMM（`lme4::glmer`、ラプラス近似、bobyqa）。2モデル平均の対比、Holm補正、推定できない対比の保留（3.3）、Holm を置き換えて比べる感度分析（4）、送り手別の対比、交互作用の尤度比検定、分散成分（分散の尺度、プロファイル信頼区間、失敗時はパラメトリック・ブートストラップ500回）。`glmm_results.json`。分散成分のブートストラップに切り替わると、1結果変数あたり数分〜十数分かかる |
| `boot_desc.py` | 3.4、4、5、6 | ケース単位のクラスター・ブートストラップ（B = 10,000、シード 20261119）による条件別の率と率の差（どちらも95%信頼区間）、H5の非劣性、未送信の内訳、補助列、LT6の別集計、H1〜H3の記述。`boot_desc_results.json` |

## 実行に必要なもの

- Python 3.10以上、numpy、scipy
- R と lme4、jsonlite。作成時の動作確認は R 4.3.3、lme4 1.1-35.1、Matrix 1.6-5（Ubuntu 24.04 のパッケージ `r-base-core`、`r-cran-lme4`）。実際に使った版は `glmm_results.json` に記録されます。

## 計画に書いていない実行上の決まり

- 率はすべて、予定したエピソード全体を分母にする（計画4章）。
- `prep.py` の `--no-hash-check` は開発用の記録（split=dev）にだけ使える。本番（split=main）に付けると停止する。
- `glmm.R` は、分散成分の信頼区間以外を `glmm_results.json` に先に書き、分散成分を `glmm_varcomp.json` に結果変数ごとに書き足す。`--dev-quick`（ブートストラップ20回）は開発用の記録にだけ使え、本番では停止する。

## 動作確認

- 開発用の動作確認の記録（`operation-checks/dev-smoke-20261118-03/`）で、3つのスクリプトが最後まで動くことを確かめた。完全分離による推定不能（3.3の手順3）、ブートストラップ、LT6の別集計、H1・H3の集計の経路もこの記録で動いた。
- `split` を main に書き換えた開発記録で、`--no-hash-check` を付けると停止し、付けないと照合で停止することを確かめた。
- ケースの分散がある合成データ（720エピソード）で、分散の尺度の区間がプロファイルの標準偏差の区間の両端を二乗した値になること、プロファイルが失敗した結果変数でブートストラップに切り替わることを確かめた。
- 感度分析の比較は、レビューの例（主検定の補正前 p = 0.03、Holm 後 0.09、感度分析 0.02）で、置き換え後の Holm が 0.06 になり、補正前の値では判定しないことを確かめた。
- 開発用・合成の結果は保存していない。本番runにはまだ当てていない。
