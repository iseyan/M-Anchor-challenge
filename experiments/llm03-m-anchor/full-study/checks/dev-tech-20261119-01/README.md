### ページのリセット（0:1）

511件目の応答の後、Playwright のページが about:blank に戻り、ループが止まった（原因はこちらの確認呼び出しのタイムアウトと見られるが、確定していない）。サービスは送信中だった1件を保持期限（60秒）の後に TRANSPORT_LOST として1回分に数え、新しいページのループが同じ呼び出しの2回目の試みから続けた。成功が記録された呼び出しの再送はなく、記録の再生とエピソードは一致した。実環境での中断・再開の確認にもなった。

### gemma の HTTP_ERROR（Ollama の「prediction aborted, token repeat limit reached」、HTTP 500）

第2段階の6呼び出しで3回とも失敗、3呼び出しで1回目だけ失敗して2回目で成功した。初回試験（`main-runs/main-20261118-01`）でも gemma の第2段階で27/480件の呼び出しが同じ理由で失敗しており、新しい現象ではない。採点は凍結済みの規則どおり（呼び出し失敗・引き継ぎの送信失敗）。

### 第1段階の切断（gemma 2件）

V-AT6-D01 と V-LT3-D01 の第1段階が、有効なJSONの後に意味のない文字列（空白・ログ風の文字列）を出し続けて num_predict 300 に達した。どちらもJSON部分は解釈でき、第2段階は全条件で実行された。初回試験でも gemma の第1段階で1/120件あった。num_predict は変えない。

### 形式（第2段階・引き継ぎの状態、条件別）

技術的な状態の件数のみ。0:1（qwen）は全条件で OK 32・SENT 32。1:1（gemma）は `verify-shard-1-r1.json` の `stage2_status_by_condition`・`handoff_status_by_condition` を参照（SCHEMA_ERROR は条件ごとに2〜8件、HTTP_ERROR は計3件）。

### 動的イベント（両分割とも）

AT8 の取消18件、AT9 の使用済み18件、LT4 の承認到着18件（2ケース×9条件）。LT4 は全エピソードで提出2回、承認到着後の共有の第1段階が各ケース1回（計2件）。AT7 の再提出は、実際の拒否があった条件だけで起きた（再生で確認）。
