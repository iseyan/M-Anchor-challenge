# 凍結と本番測定の手順（実験2）

最終分析計画（`analysis-plan-final.md`）に従う。各段階の記録はGitHubに残す。

1. **人による確認の記録**：`checks/human-review-20261119/record.csv` と同フォルダの `README.md`（確認した範囲・未確認の範囲・判断）をコミットする。
2. **凍結の判断（利用者）**：判断を受けて、凍結のコミットを作る。内容は `config.json` の `run_enabled` を true にすること、凍結記録（コミット、`sources()` のハッシュ、ケースファイルのハッシュ、モデルのダイジェスト、最終分析計画のコミット）の追加。凍結のコミットより後に、本番の採点・プロンプト・ケースを変えない。
3. **本番の実行**：凍結のコミットの写しをPCに置き、新しい実行フォルダ（例：`fullstudy-main-YYYYMMDD-01`）で6分割（0:1、1:1、0:2、1:2、0:3、1:3）を PowerShell のループで順に起動する。`--split main`、上限なし。ページのループは `persist` で待機させる。所要は通しで約22時間（qwen 1分割 約3.1〜3.4時間、gemma 約3.9〜4.1時間）。途中で止めても、保存済みの呼び出しは送り直さずに再開できる。同じ実行フォルダは再開にだけ使い、やり直す場合は新しい名前にして前の記録も残す。
4. **照合**：分割ごとに記録を取り込み、`runner/verify_campaign.py` で再生の一致・エピソードのバイト一致・環境照合・再試行の枯渇と打ち切りを確かめる。
5. **報告**：6分割のエピソードをまとめ、`analysis/report_final.py` で記述報告を作る。件数・率・対応のある率差（点推定）、見届けたい3点、gemmaのA2のトークン数の差、未判定の項目（主検定・同等性・非劣性）を明記する。この報告をもって実験2を完了とする。結果を理由にケース・推定法を追加しない。
